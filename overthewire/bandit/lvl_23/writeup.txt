I successfully exploited a privilege escalation vulnerability by leveraging a scheduled script that runs as the bandit24 user. Here's how it worked: First, I created a malicious payload script called bandit24.sh using the command echo "cat /etc/bandit_pass/bandit24 > /tmp/wo.txt" > bandit24.sh. This script simply reads the password file for the bandit24 user and saves the contents to a temporary file. Next, I made the script executable for everyone by running chmod 777 bandit24.sh, which ensures that the bandit24 user can run it. I then placed this script in the directory /var/spool/bandit24/foo/, which is a location that the bandit24 user continuously monitors and executes scripts from.

My bash script then enters this directory and loops through all files it finds, checking if they are owned by the bandit24 user and are regular files (not directories). When it identifies files owned by bandit24, it executes them with a 60-second timeout using the timeout command, which will force-kill the script if it runs too long. Because the script runs as the bandit24 user, my payload script had the necessary permissions to read /etc/bandit_pass/bandit24 — a file that only the bandit24 user can access. My payload wrote the password to /tmp/wo.txt, which I could then read with cat /tmp/wo.txt, revealing the bandit24 password: hVQMk3lJNsmQ7VF3ubyrNNBom7BOgVXv. This technique is a classic privilege escalation attack that exploits scheduled tasks running as more privileged users.
